我的第一个 AI 项目：考研数学刷题平台

2026.10.02 AI 工程 20 min read

the first ai program —— 这是我给自己的第一个 AI 项目起的目录名。 它不是一个玩具 demo，而是一个真的有人在用的考研数学刷题平台： Spring Boot 3 + MyBatis + MySQL 8 + Vue 3，包含题库、练习、报告、复习四大模块。

更有意思的是它的演进路径。这个项目没有一步到位，而是分了三版走： V1 先把纯业务系统做扎实，V2 接入 LLM 和 Redis，V3 补上 RAG 知识检索。 每一版都对应一类面试问题，也对应一次"从能跑通到讲得清"的升级。

一、为什么是"骨架剥离学习法"

项目起点很特殊：拿到手的不是一份空白目录，而是一个骨架—— 所有业务方法都是待实现的 TODO，但配套的验收测试已经就位。

这个初始状态是设计过的，甚至"红灯"都是预期的一部分：

  • SkeletonSmokeTest（4 个用例）——全绿，证明工程结构正确。
  • MasteryCalculatorTest（10 个用例）——全红，抛 UnsupportedOperationException，这是待完成的作业。
  • EbbinghausSchedulerTest（8 个用例）——全红，同上。

刚看到满屏红色测试时我是懵的，后来才理解它的用意： 红灯不是缺陷，而是"完成"的定义。 实现对应模块，让灯一盏盏变绿——这比"照着教程敲一遍"多了一个明确的验收闭环。

配合的方法是六步循环：读契约（接口 javadoc / 测试）→ 合卷实现 → 跑测试验收 → 与 AI 生成的参考实现对比 → 记决策日志。 其中最后一步最关键，后面会展开讲。

二、V1：先把纯业务系统做扎实

第一版刻意不碰任何 AI。理由很简单： 如果连 CRUD、事务、索引都写不利索，接入大模型也只是给烂地基刷漆。 V1 按能力层拆成了 L1~L7：

  • L1 数据模型：补 resultMap、知识点树递归组装。
  • L2 题库：录入、分页、Excel 批量导入。
  • L3 练习：选题、服务端计时、判分。
  • L4 报告：聚合 SQL + 掌握度算法。
  • L5 复习：艾宾浩斯调度算法。
  • L6 前端：四个页面 + KaTeX 公式 + ECharts 图表。
  • L7 收尾：docker-compose 一键启动、压测数字、简历 bullet。

几个真正值得讲的决策

项目里我刻意维护了一份 DECISION_LOG.md： 每做一个设计选择就记一行，写清楚选了什么、备选是什么、为什么。 它同时是"想清楚"的工具和面试前的复习提纲。几条我自己比较满意的： 

| 决策点   | 选择              | 备选              | 理由                                  |
|----------|-------------------|-------------------|---------------------------------------|
| ORM      | MyBatis           | Spring Data JPA   | SQL 完全可控，索引/聚合优化都在明面上 |
| 做题计时 | 服务端计算        | 信任前端上报      | 前端数据不可信，是安全常识            |
| 导入幂等 | content_hash 唯一键 | 无判重          | 重复导入 Excel 不产生脏数据           |
| 时间获取 | 全局注入 Clock Bean | LocalDate.now() | 单测可注入固定时钟，不用改系统时间    |
| 领域算法 | 纯静态类（无 Spring） | @Service 注入  | 纯函数脱离容器可毫秒级测试            |

挑三条展开说：

① 为什么计时必须在服务端算。 如果 duration 由前端上报，用户改个请求体就能刷出"3 秒做完一套卷"的记录。 服务端用 started_at 和提交时间做差，才是可信数据。 这条背后是一个更大的原则：任何来自客户端的数据都默认不可信。

② 为什么用 content_hash 做幂等。 题库支持 Excel 批量导入，最怕的是同一份文件被点两次，直接翻倍。 做法是对题干内容算一个哈希，建唯一索引； 重复行不会插入，而是计入 duplicated 统计返回给用户。 配合 EasyExcel 流式读取 + 分批入库，几万行也不会把内存撑爆。

③ 为什么时间要注入 Clock Bean。 艾宾浩斯复习的核心是"第 1、2、4、7、15 天该复习哪些题"。 如果代码里到处写 LocalDate.now()，写单元测试就只能去改系统时间—— 不可行。把 Clock 做成可注入的 Bean， 测试时塞一个固定时钟进去，整个调度逻辑就能毫秒级验证。

这几个决策有个共同点：它们都不是"能不能跑"的问题，而是"经不经得起追问"的问题。 代码能跑通的方案有很多种，但能在被问到"为什么不用另一种"时答得上来的，往往只有一种。

三、V2：接入 LLM 与 Redis

V1 跑通之后，三个明显的短板浮出来：错题只有解析文本、没有"讲解"能力； 报告每次查看都重复聚合；平台缺少学习激励。V2 就针对这三点做增量。

F1 错题智能讲解：LLM + SSE 流式

这是 V2 的旗舰功能。用户在报告页点错题旁的"AI 讲解"， 后端流式返回一段用"高中生能听懂的话"讲这道题为什么错。

技术上有三个关键选择：

  • 走 OpenAI 兼容接口而不是绑定某个 SDK。DeepSeek、通义、GPT 都是同一套协议，换模型只改配置，不改代码。
  • 用 SSE 而不是 WebSocket。讲解是单向推送，SSE 基于原生 HTTP、断线自动重连，比 WebSocket 轻得多。
  • 讲解生成后落库。同一道题第二次查看直接读库，不再调模型——这是最直接的成本控制手段。

还有一条容易被忽略但很关键的：降级路径。 LLM 超时或报错时，接口返回解析文本加一句"AI 暂不可用"， 页面绝不能 500。依赖外部服务的地方，都要预设它挂掉的样子。

F2 报告缓存：Cache Aside

报告是一次聚合查询，每次看都重算太浪费。做法是： 生成时把报告 JSON 快照写进 Redis，key 是 report:{userId}:{date}； 读的时候先查缓存、未命中回填；练习提交后先更新 DB，再删缓存。

这里有个经典追问："为什么不是先删缓存再更新 DB？" 因为那种顺序在并发下会留下脏数据窗口。顺带把缓存三件套也理了一遍：

  • 穿透：查一个不存在的 key，每次都打到 DB。→ 空值也缓存。
  • 击穿：热点 key 过期瞬间，大量请求同时压向 DB。→ 互斥锁或逻辑过期。
  • 雪崩：大量 key 同时过期。→ TTL 加随机抖动。

F3 打卡排行榜：Redis ZSet

按月建 ZSet，ZINCRBY 打卡累加，ZREVRANGE 取 Top10， ZRANK 查自己的排名。为什么不用 MySQL 排序？ 深分页慢，而且实时排序成本高。ZSet 底层是跳表 + 哈希， 插入和排名查询都是对数级，天然适合这个场景。

V2 里最值得记住的一句话：v1 为什么不加 Redis？因为量小，加了是过度设计。 v2 为什么加？因为量大了，不加是欠设计。 同一个技术决策，在不同阶段可以是完全相反的答案。

四、V3：RAG 知识检索

V2 上线后会暴露一个问题：LLM 讲考研数学时会幻觉—— 编造公式、讲错定理的适用条件。因为它靠的是通用知识，没读过这本教材。

解法是 RAG（检索增强生成）。基本流程分离线在线两段： 

离线：知识点文档 → 切片 → Embedding → 存入向量库
在线：用户错题 → Embedding → 向量库 Top-K 相似检索 → 拼进 prompt → LLM 生成

几个设计要点：

  • 切片策略：按知识点小节切，每片 300~500 字，带 10%~20% 重叠，并保留知识点 id 作为元数据，方便溯源。
  • Top-K 取 3~5：太少覆盖不足，太多又贵又引入噪声。
  • 向量库起步选 Redis Stack：复用 V2 已有的 Redis，零新增组件，学习成本最低。
  • 检索不到就降级：明确告诉用户"未找到教材依据"，而不是硬编一个答案。

RAG 让答案从"模型记得什么"变成"教材上写了什么"， 这是它比单纯调 API 高一个档次的根本原因—— 它把不可控的生成，建立在可控的检索之上。

五、这个项目真正教给我的

写完三版回头看，最大的收获不是学会了几个框架，而是三件事：

  1. 迭代要有边界。 V1 不碰 AI，V2 不碰向量检索， 每一版都明确写清楚"这一版不改什么"。避免一次改动过大， 是让项目能持续走下去的前提。
  2. 每个选择都要能讲出备选。 "我用了 MyBatis"是陈述，"我选 MyBatis 而不是 JPA，因为本项目的主要学习素材是 SQL 优化"才是回答。 决策日志逼我把前者补成后者。
  3. 先能跑通，再谈优雅。 服务端计时、content_hash 幂等、Clock 注入这些设计，单独看都不复杂， 但组合起来就让整个系统"经得起问"。而它们的共同前提是—— 业务本身已经跑通了。

这是我第一个 AI 项目，目录名起得很朴素。 但它让我明白了一件事：AI 应用的难点从来不在"调用模型"， 而在模型之外的那一整套工程——数据怎么来、结果怎么存、挂了怎么办。
