从零搭一个 MOSS 风格的个人博客

2026.09.28 杂谈 12 min read

想搭个人博客很久了。中途试过现成的主题——装完确实快，但改到第三天就发现， 每一处想动的地方都在跟主题的默认样式打架。于是干脆推倒，从零写一套。

视觉目标很明确：那种黑白单色打底、荧光绿做唯一强调色、用锐利斜线切割画面的 技术海报感。它看起来复杂，拆开之后其实是三条规则加一点几何计算。

一、把风格拆成三条规则

大多数"高级感"设计不是靠堆元素，而是靠约束。这套视觉的约束只有三条：

  1. 只有三种颜色：纯黑、纯白、荧光绿。灰度只允许作为过渡，不允许出现第四种色相。
  2. 绿色只做强调：面积占比控制在 10% 以内。它一旦变成主色，整个页面就从"克制的技术感"滑向"廉价的赛博朋克"。
  3. 所有边界都是斜的：横平竖直只留给文字，容器、色块、过渡带一律带角度。

第三条是这套视觉最核心的部分。人眼对斜线比直线敏感得多， 一条 30 度角的切割线能让整块版面立刻"活"过来。

二、设计 token 先落地

动手写组件之前，先把颜色、字体、间距全部收进 CSS 变量。 后面所有组件只引用变量，这样换配色只需要改一处。 

:root {
  --ink: #000000;        /* 黑：基底 */
  --paper: #ffffff;      /* 白：基底 */
  --neon: #00ff41;       /* 荧光绿：唯一强调色 */
  --neon-deep: #0a8f2a;  /* 深绿：白底上的可读替代 */

  --mono: "JetBrains Mono", ui-monospace, Consolas, monospace;
  --cjk: "Noto Sans SC", -apple-system, "PingFang SC", sans-serif;

  --ease: cubic-bezier(0.16, 1, 0.3, 1);
}

这里有个容易被忽略的细节：荧光绿在白底上几乎不可读。 所以我准备了两档绿色——黑底用 --neon， 白底用压暗过的 --neon-deep。同一套语义，两种明度。

三、斜线场：程序化几何，不是贴图

首页背景那一片放射状的黑白碎片，是整套视觉里最"唬人"的部分。 如果去找素材图，会有三个问题：图片体积大、无法随窗口自适应、而且每张图的角度都是固定的， 放到不同尺寸的容器里就会露馅。

所以改成用代码生成几何。核心逻辑很简单：从一个焦点出发， 按一个主方向角度撒出若干条线，每条线的角度做小范围随机扰动， 长度拉到足够长使其跑出画布，宽度则用幂函数制造"细头粗尾"的锥形碎片感。 

function shardField(svg, opt) {
  var rnd = mulberry32(opt.seed);      // 可复现的伪随机
  var fx = opt.focal.x * W;            // 焦点坐标
  var fy = opt.focal.y * H;

  for (var i = 0; i < opt.count; i++) {
    // 角度：主方向 + 扰动
    var ang = opt.axis + (rnd() - 0.5) * opt.spread;

    // 长度：拉到足够跑出画布
    var d0 = rnd() * 240;
    var len = 420 + rnd() * 2200;

    // 宽度：幂函数让大部分细、少数粗
    var wEnd = 1.5 + Math.pow(rnd(), 2.4) * 34;

    drawSplinter(fx, fy, ang, d0, len, wEnd);
  }
}

三个参数决定了最终的观感：

  • axis 是主方向角。改成 -0.62（约 -35 度）就是首页那种向右上冲的姿态。
  • spread 控制散布宽度。太小会变成一束激光，太大会散成杂乱毛刺，2.2 ~ 2.5 是甜区。
  • Math.pow(rnd(), 2.4) 是关键——它让宽度的分布严重右偏，于是 90% 的碎片都很细，只有少数几条粗得刺眼。这正是海报里那种层次感的来源。
用 mulberry32 这类带种子的伪随机，是为了让同一页每次刷新长得一样。 如果直接用 Math.random()，用户每刷新一次背景就换一个样，会显得很廉价。

四、故障字：clip-path 加图层位移

标题上的"故障"效果没有用任何库，本质是两个绝对定位的副本： 

.glitch__layer--a {
  color: var(--neon);
  transform: translate(-0.022em, -0.014em);
  clip-path: polygon(0 0, 100% 0, 100% 42%, 0 42%);
}

.glitch__layer--b {
  color: var(--grey-70);
  transform: translate(0.02em, 0.016em);
  clip-path: polygon(0 58%, 100% 58%, 100% 100%, 0 100%);
}

clip-path 只保留副本的一条水平带，位移制造错位， 再用 steps(1) 的 keyframes 偶尔改变裁切区间—— 于是就有了"信号不稳"的闪烁。用 steps(1) 而不是平滑插值，是因为 真实故障是跳变的，平滑过渡反而假。

五、斜切过渡带

黑白区块之间的斜线接缝，用了一个很省事的技巧：一个容器，背景是上一块的颜色， 内部伪元素铺满并填下一块的颜色，再给它一个三角形的 clip-path。 

.slant {
  position: relative;
  height: clamp(38px, 5vw, 78px);
  background: var(--a);          /* 上一块的颜色 */
}

.slant::after {
  content: "";
  position: absolute;
  inset: 0;
  background: var(--b);          /* 下一块的颜色 */
  clip-path: polygon(0 100%, 100% 0, 100% 100%);
}

这样接缝天然严丝合缝，不用去算负 margin，也不怕响应式下高度变化。

六、为什么不做音乐盒和飘花

参考的站点里挂了音乐播放器和满屏飘落的花瓣。它们确实"有氛围"， 但代价是：每次进页面都要等音频加载、移动端自动播放被拦截、 花瓣在低端机上掉帧，而且——它们和内容没有任何关系。

这套视觉本身已经足够"满"了：放射的碎片、闪烁的标题、滚动的色带。 再加动态元素，观感会从"克制"变成"吵"。 设计里最难的不是加，是忍住不加。

结语

整个站点最后是零依赖、零构建的：一个 CSS 文件、一个 JS 文件、几个 HTML 页面， 直接丢到 GitHub Pages 就能跑。写文章时复制一份模板改内容即可。

如果你也想做类似的视觉，建议从先定约束开始—— 规定好"只能用哪三种颜色""哪些形状禁止出现"， 剩下的决定会突然变得很容易。
