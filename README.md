# QIANMI // 个人博客

一个黑底终端风格的个人博客。**纯静态 HTML / CSS / JavaScript，不用任何框架、不用打包工具**，直接托管在 GitHub Pages 上。

整个项目是我和 AI 工具协作完成的：我负责定设计、提需求、做审查和验收，AI 负责把代码写出来。

在线访问：<https://qianmi-qm.github.io>

---

## 这是什么

这是我自己的个人主页 + 博客站点，包含三个页面：

| 页面 | 文件 | 作用 |
|------|------|------|
| 主页 | `index.html` | 首页大标题、跑马灯、最新文章、项目、关于我 |
| 文章 | `archive.html` | 文章归档列表 |
| 项目 | `projects.html` | 项目展示 |

目前文章和项目还是空的（内容在陆续补），但站点的骨架、视觉和交互都已经完成。

## 为什么不用框架

现在做一个博客，用 Hexo、Vue、React 都很方便，但我故意选了"最原始"的做法：

- **不用 npm、不用 `npm install`、不用打包**——想改哪里就直接改那个文件，改完推上去就生效。
- **没有构建步骤**，也就不存在"构建失败""依赖版本冲突"这些问题。
- **页面很小、加载很快**，没有一堆第三方库要下载。
- **没有框架和主题的束缚**，想做什么效果就自己实现，不用去迁就某个现成主题的样式和结构。

唯一的"外部依赖"是 Google Fonts 上的两套字体（JetBrains Mono 和 Noto Sans SC），用来保证中文和等宽字体的显示效果。

## 这个项目是怎么做出来的（AI 协作）

坦白说，这个站点的代码基本是 AI 写的，我做的是"提需求 + 定方向 + 审查验收"。具体分工是这样的：

| 环节 | 我做的 | AI 做的 |
|------|--------|---------|
| 定方向 | 视觉风格（黑底 + 荧光绿 + 斜切、不要圆角）、技术约束（零依赖、零构建）由我拍板 | —— |
| 写代码 | 逐块提需求、描述想要的效果 | 生成 HTML 结构、CSS 样式、JS 交互的初版 |
| 调试 | 把"哪里不对"描述清楚（比如跑马灯文字上下留白不等宽、碎片场构图太乱），判断方案要不要采纳 | 分析原因、给出修改方案、改代码 |
| 审查验收 | 在浏览器里实际看效果，不满意就继续调；读一遍 AI 写的代码，确认逻辑和安全性没问题 | —— |
| 学习 | 对不熟的东西（`clip-path` 写法、SVG 路径、响应式单位）要求讲清原理，而不是照抄 | 解释原理、拆解概念 |

这么做的结果是：国庆假期几天时间里，做出了一个从视觉到交互都完全定制的站点，同时也把"怎么把 AI 用成真正的生产力工具"这件事练了一遍。

核心体会是：**AI 负责产出，人负责判断**。AI 能很快写出能跑的代码，但"要什么样的效果、这样写对不对、要不要采纳"这些决定，还得自己做——不然做出来的就是一个自己都讲不清楚的东西。

## 站点有什么特别的

### 1. 首页那些黑白碎片，是代码算出来的，不是图片

首页和各个页头背景里那些闪电、三角形、楔形碎片，**没有一张是图片**，全部是 JavaScript 现场生成的 SVG 图形。

每个页面只需要给一组参数，就能算出完全不同的构图：

```html
<svg data-shard-field='{
  "seed": 11,                    // 随机种子：同一个种子，每次生成的结果一模一样
  "focal": {"x": 0.76, "y": 0.24}, // 焦点位置：碎片从画面哪个点向外飞散
  "flow": -155,                  // 主飞散方向（角度）
  "density": 1.0,                // 碎片密度
  "beams": 2,                    // 对角宽梁的数量
  "contrast": 0.42,              // 楔形碎片的强度
  "greenRatio": 0.32             // 荧光绿的占比
}'></svg>
```

也就是说，**换个 `seed` 就是一张全新的画面**，但同一个 `seed` 每次刷新都长得一样（可复现）。窗口变大变小，构图会自动跟着适配。

生成器分了 8 层来堆叠画面：氛围雾块 → 闪电 → 细三角针群 → 楔形 → 对角宽梁 → 切缝 → 水平细线组 → 十字标记，再叠一层滚动视差。

### 2. 全站只有三种颜色

纯黑 `#000`、纯白 `#FFF`、荧光绿 `#00FF41`。没有第四种颜色。

为了避免大块黑底太单调，用四档"接近黑"的明度差（`bg` / `bg-2` / `bg-3` / `bg-4`）让区块之间交替，视觉上能分得出层次，但看起来仍然是纯黑。

### 3. 所有边角都是"切"出来的

整个站点**没有一个圆角**。卡片、按钮、区块的直角都用 `clip-path` 斜着切掉一块，区块与区块之间也用斜切过渡带衔接。

### 4. 其他细节

- **跑马灯**：全站统一的滚动字幕条，上方有「竖线 + 绿点 + SCROLL」指示器，下方接一条通栏荧光绿装饰条。
- **故障字（glitch）**：大标题鼠标移上去会有故障闪烁效果。
- **滚动揭示**：内容滚动到视口内时会依次淡入。
- **响应式**：用 `clamp()` 和 `vw` 做自适应，手机和宽屏都适配。

## 本地怎么跑

不需要装任何东西，**直接双击 `index.html` 就能在浏览器里打开**。

如果你更习惯用本地服务器预览（推荐，行为跟线上更一致）：

```bash
python -m http.server 8000
# 然后打开 http://localhost:8000
```

## 怎么发布

这个仓库本身就是 GitHub Pages 的源仓库：

1. 改完代码，提交并推送到 `main` 分支；
2. GitHub 会自动构建，通常 1~2 分钟后生效；
3. 访问 <https://qianmi-qm.github.io> 查看（如果没变化，按 `Ctrl + F5` 强制刷新缓存）。
